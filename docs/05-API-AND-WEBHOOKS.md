# 05 — Public API and outgoing webhooks

## 1. API principles

- REST/JSON under `/api/v1`.
- OpenAPI 3.1 is the contract.
- Cursor pagination, not page numbers.
- ISO 8601 UTC timestamps.
- Money is `{ amount: "1000", currency: "gbp" }` or integer-as-string to avoid JavaScript precision ambiguity at boundaries.
- Stable opaque IDs; slugs are lookup aliases.
- ETags and conditional GET for public resources.
- Problem Details (`application/problem+json`) for errors.
- No GraphQL in v1.

## 2. Authentication classes

### Public

No token; aggressive caching and rate limits.

### Supporter session

Better Auth cookie for first-party browser calls. CSRF protection on state-changing requests.

### Project API key

Scoped key with prefix, random secret shown once and hashed at rest.

Example scopes:

```text
project:read
posts:read
posts:write
tiers:read
goals:read
goals:write
supporters:read
analytics:read
webhooks:manage
```

No permanent API key can create arbitrary payments. Checkout-session creation requires a short-lived browser/server intent tied to project, amount and origin.

### Platform internal

Separate service credentials/private network, never project keys.

## 6. Checkout intent

```text
POST /api/v1/projects/{slug}/checkout-intents
```

Request contains selected amount, tier/cadence, supporter tip and public preferences. Response contains a short-lived intent ID and embedded Checkout client secret/URL. The server recomputes every amount and application fee.

Idempotency header is required for authenticated integrations and generated by the first-party client for double-click protection.

## 7. Rate limits

Use a PostgreSQL-backed coarse limiter for authenticated/project keys and Cloudflare rate rules for public abuse. Initial policy:

- Public reads: 120/minute/IP with cache hits excluded where possible.
- Search: 30/minute/IP.
- Checkout intents: 10/10 minutes/IP and 20/hour/account.
- Email OTP sends: 5/hour/email and 10/hour/IP, plus escalating cooldown.
- Project API keys: plan-independent default 600/minute/project with burst 60; tighten expensive analytics/export routes.
- Outgoing webhook replay: 20/minute/project.

Rate-limit response includes `Retry-After` and standard headers.

## 8. Outgoing event envelope

```json
{
  "id": "evt_01J...",
  "type": "membership.renewed",
  "api_version": "2026-08-01",
  "created_at": "2026-08-28T20:00:00Z",
  "project_id": "prj_01J...",
  "data": {
    "object": {}
  }
}
```

Event payloads contain oss.tips IDs and necessary project/support state, not Stripe secrets or supporter email by default.

## 10. Signatures

Headers:

```text
oss-tips-event-id: evt_...
oss-tips-timestamp: 1787947200
oss-tips-signature: v1=<hex hmac sha256>
```

Signed bytes:

```text
{timestamp}.{raw_request_body}
```

- Reject timestamps outside five minutes unless replaying from dashboard.
- Secrets are 32+ random bytes, shown once, stored encrypted and can rotate with overlap.
- Documentation includes constant-time verification examples.

## 11. Delivery policy

- HTTPS only.
- DNS resolution and destination validation at creation and every delivery.
- Block loopback, link-local, RFC1918, metadata and internal service ranges; re-check after redirects and DNS changes.
- No redirects in v1, or maximum one redirect after complete revalidation.
- 5-second connect, 10-second total timeout.
- Maximum response body captured 4 KB and redacted.
- Success is any 2xx.
- Retry with jitter for up to 72 hours.
- Stable event ID across retries.
- Manual replay creates a new delivery attempt, not a new event.
- Disable endpoint after sustained failures and notify project.

Suggested retry schedule:

```text
0s, 30s, 2m, 10m, 30m, 2h, 6h, 12h, then every 12h to 72h
```

## 12. Versioning

- URL major version changes only for broad contract breaks.
- Each event includes `api_version`.
- Project webhook endpoint pins a version.
- Additive fields may appear at any time; consumers must ignore unknown fields.
- Breaking event changes get a new version with at least a six-month migration window after beta.
